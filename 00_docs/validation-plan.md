# 検証計画

## 検証する問い

7日間で決めた範囲を再現し、アプリの動作とNext.jsの設計判断・理解の穴・実務との差を、観測した証拠に基づいて説明できるかを確認する。チュートリアルの完走やbuild成功を、本番運用可能性の証明とは扱わない。

## 成功条件

- briefに定めたDay別の主要経路を実施し、未達・対象外も理由とともに記録している。
- 各日の記録で、教材の指示、実施内容、観測事実、自分の解釈、設計判断、未検証事項が別の欄に記録されている。
- 少なくとも1つの設計判断を伴う変更について、前提・選択理由・確認結果・限界を説明できる。
- Day 7にproduction buildと採用した公開前確認の結果を残し、実公開の可否をMVP達成と分けて判断している。

## 記録先

日ごとの記録は[`learning-record-template.md`](learning-record-template.md)を使い、各Dayの内容を子repoの`00_docs/learning-records/day-<n>.md`へ記録する。各欄の役割は以下の通り。

| 区分 | 記録する内容 |
|---|---|
| 教材の指示 | 公式教材が要求・説明している手順や制約。教材URL、確認日、版も添える |
| 実施したこと | 実行した変更、コマンド、入力条件 |
| 観測した事実 | 画面・レスポンス・ログ・テスト結果など再確認できる結果。解釈を混ぜない |
| 自分の解釈 | 観測から考えた理由や理解。教材に明記された事実と区別する |
| 設計判断 | 採用・不採用、判断条件、代替案、選択理由 |
| 未検証事項 | 確認できなかった条件・残る疑問・実務との差 |

`learning-records/`は各日の作業時に必要な記録だけ作る。記録ファイルを先行して空作成しない。企画全体の成功条件・証拠・公開判断は本書、企画の問い・スコープ・環境は[`brief.md`](brief.md)を正本とする。

## 証拠と確認方法

| 観点 | 確認する証拠 |
|---|---|
| 再現性 | 固定した教材URL・版、実施環境、setup/起動手順、コマンド |
| ルーティング・UI | Day 1は`/`・`/about`・`/watch/[id]`へのアクセスと画面遷移を確認し、後続の日に検索・チャンネル画面と動画ページの対話UIを確認する |
| データ取得・更新 | 動画・チャンネルの表示、検索結果と検索結果なし、動画ページ上のいいね・コメントなどの操作、loading/errorの観測 |
| キャッシュ・API | 初回表示・再訪・更新直後の比較、Route HandlerとServer Functionの確認 |
| 品質・安全性 | 選定テストの対象と結果、入力・操作の失敗時挙動、Secret確認、アクセシビリティ・性能の確認または未計測理由 |
| 公開準備 | production build、採用CI、公開素材・権利・環境・運用上の制約確認。実公開はbriefの判断条件を満たし、企画オーナーの別途判断がある場合のみ |
| 設計判断 | 学習記録に残した前提・代替案・採用理由・結果・限界 |

記録の際は、実際に行った手順・結果だけを完了として記載する。実施できなかった確認は成功扱いにせず、理由・影響・次の確認条件を未検証事項に残す。

## コマンド

2026-09-24時点のpackage.json scriptsは`dev`、`build`、`start`、`lint`。`typecheck`と`test` scriptsはまだ定義されていない。初期の検証コマンドは以下とし、実施日には出力と終了結果を学習記録へ転記する。コマンドやテスト方式を追加・変更したら理由も記録する。

```bash
npm ci
npm run lint
npx tsc --noEmit
npm run build
```

テストは対象リスクを見て方式を選び、必要なtest scriptを追加した場合のみ実行・記録する。コマンドを定義しただけで検証済みとはみなさない。
